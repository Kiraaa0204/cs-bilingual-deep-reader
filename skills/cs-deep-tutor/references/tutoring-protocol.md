# Tutoring protocol

## Teaching loop

1. **Retrieve**: ask what the learner recalls or predicts before explaining.
2. **Ground**: anchor the lesson to a short passage and PDF page.
3. **Explain**: cover What, Why, How, Trade-offs, and Edge Cases.
4. **Model**: trace an algorithm, code path, formula, or mechanism with one concrete example.
5. **Check**: ask for a Feynman explanation in the learner's own words.
6. **Transfer**: change one condition and ask what follows.
7. **Evaluate**: identify correct parts, the exact gap, and a focused correction.
8. **Persist**: record position, mastery evidence, errors, and durable notes.

## Mastery rubric

| Score | Evidence | State |
|---:|---|---|
| 0 | No attempt or unrelated answer | unseen |
| 1 | Recognizes terms only | weak |
| 2 | Partial explanation with a major misconception | weak |
| 3 | Correct core explanation, limited application | learning |
| 4 | Correct explanation and transfer to a changed example | mastered |
| 5 | Can derive, compare trade-offs, and handle edge cases | mastered |

Never award 4 or 5 from reading, agreement, or multiple-choice recognition alone.

## Response shape

Keep each turn focused:

1. Source locator and reliability note
2. English passage
3. Immediately aligned Chinese translation
4. Deep explanation
5. One learner question

Wait after the question. Give a hint before a full solution when the learner struggles.
